# Pascal

Enable `aux-rs` with `pascal` for native models, codecs and injected I/O. Add `http` and/or `ws` only when standard networking is needed; exchange selection alone does not enable a runtime or socket stack. Constructors accept explicit deployment environments and custom endpoint maps. `with_transport` accepts caller-owned I/O. Standard clients expose their transport for deterministic `shutdown`.

`PascalClient` exposes `read` and `write` namespaces, preserving native long/short positions, string quantities, sequences, cursor pagination and per-entry batch outcomes. Select `Pascal::mainnet()` (deployment 3) or `canary()` (deployment 2); `custom` overrides service endpoints without changing signing deployment.

`PascalAuth` separates the owner wallet from a trading key. `LocalSigner` or a caller-provided `Signer` signs final permit bytes. Trading permits use the published little-endian binary layouts and zero reserved bytes; wallet/profile permits use ordered compact JSON arrays. Native Ed25519 signatures are base58. Owner-only operations reject trading-key authority. Wallet timestamps are monotonic across client instances and concurrent submissions; wallet writes with uncertain outcomes remain blocked until the caller explicitly calls `reconcile_wallet` after reconciliation.

Read and write WebSockets are distinct. `Subscription { service: "read".into(), params: <native subscribe mapping> }` uses the data feed; `open_rpc` exposes place/cancel/mass-cancel/ping on order entry. A single outstanding command preserves correlation after timeout, disconnect or cancellation. Native sequences remain visible; noncontiguous global Pascal sequence numbers are not treated as missing local updates.

`PascalChainClient` prepares an SPL Token `transferChecked` to an explicit deposit token account. Configure Solana RPC, published USDC mint and precision explicitly. Preparation validates token programs, mint, owner and decimals; signing verifies transaction metadata and signer identity. Submission checks block height and sends once (`maxRetries: 0`). Confirmation and delayed API deposit credit are separate: query signature status and the API transfer history/account snapshot. Python `reconcile_deposit_credit` returns both native reports. The published transfer history does not guarantee a Solana signature field; callers must correlate its native amount/sequence/time and page history explicitly. Never infer credit from RPC acceptance alone. `clear_reconciled_submission` requires explicit caller attestation after external reconciliation. Withdrawals and key changes stay on their signed API routes. The matching engine alone submits settlements; no private program instructions or account layouts are invented.

## Requests, values and Python

Every REST operation has a named async method; the inventory maps `40` REST operations and `25` WebSocket message contracts. Rust request types are under the service namespace and end in `Params`. Path/query/header fields are at the top level and JSON request bodies are under `body`. Unknown response fields and explicit nulls are retained. Native numeric strings remain strings; JSON numbers use arbitrary precision rather than binary floating point.

Python exports matching clients and local/async callback signers from `aux_py`. Use `async with Client(...) as client` or `await client.aclose()`. Constructors accept `network`, `endpoints`, `websocket`, timeout and bounded subscription capacity. Requests are native mappings with the same `body` envelope as Rust. Python floats are rejected recursively; use `Decimal`, integers or native strings. Responses preserve JSON integers, decode fractions to `Decimal`, and keep string-encoded decimals as strings. Native errors carry venue/status/code/body fields. `Subscription` supports async iteration and explicit close; parent shutdown cancels children. Command helpers live in `aux_py._prediction_rpc` and are returned by `open_rpc()`.

Writes execute once. Transport errors with unknown outcomes require explicit caller reconciliation against order IDs, transaction hashes or native history. Public idempotent reads may use the bounded standard retry policy; signed reads are prepared afresh per call and are not automatically retried. Client close/cancellation never silently repeats a write.
